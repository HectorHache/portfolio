1. **Live beats static** — running systems + real dates are the only un-fakeable proof in an AI-generated world.
2. **Public-safe only** — no third-party PII, no keys, no internal paths. Blur where needed.
3. **Evidence rule** — no project card without a link, screenshot, or metric. Empty cards kill credibility.
4. **Staged, not launched** — portfolio is a rolling system with a queue (SHIPPED / SHIPPING / GROWING).
5. **Approval-gated** — every content change passes Mick's gate after agent verification. Trust contract with recruiters = never auto-publish unverified claims.

## Private repos & authenticity — decisions
- **Repos are NOT required** for agentic roles; live systems > code. Recruiters rarely clone.
- Authenticity stack: live URLs → dated screenshots → metric write-ups → consistent identity (one handle everywhere) → 2-3 public repos.
- Public repos (max 3): portfolio site, setupclone, one sanitized flagship. Generated by **one-way allowlist export** (reuse setupclone sanitization machinery). NEVER mirror private repos.
- PID rules: no third-party identities, no internal data, no keys. Chat·hector = blurred screenshots only. Vault = diagrams only.
- "Private by design" is a *feature* to sell (data-protection maturity — NL/DE market loves it).
